# 浏览连续性与模型加载体验优化

**目标：** 完成用户授权的新一版优化，验证后提交、推送并重新构建启动本项目容器。

**设计：** 沿用当前蓝白色医学科普界面和医学内容。疾病筛选与选中项提升到应用层，页面切换保留浏览上下文；模型分别处理基础资源状态与可选图层错误。相比新增全站路由或重做页面，本轮优先修复已确认的使用中断，避免扩大架构范围。

## 实施步骤

1. `src/lib/catalog.ts`、`src/components/KnowledgeViews.tsx`：增加受控疾病目录状态及合法选择规则；药物搜索统一多词匹配，提供空结果重置。`tests/catalog.test.ts` 验证入口、组合筛选、选中项与搜索。
2. `src/App.tsx`：持有疾病目录状态，器官直达疾病时明确更新；移动端目录提供焦点约束、Escape 关闭和焦点返回，输入/弹窗中不触发全局搜索快捷键。
3. `src/components/knowledge.css`、`KnowledgeViews.tsx`：窄屏提供阅读详情与返回目录入口，跳转后转移焦点；来源说明与仓库中 Human Atlas 署名保持一致。
4. `src/components/AnatomyScene.tsx` 及独立辅助模块：基础模型加载/就绪/失败同步到界面；可选图层失败不中断基础模型，按需重试；处理 WebGL 上下文丢失，减少未变化标签的 React 更新。
5. 运行完整测试、生产构建、桌面/窄屏浏览器操作检查；检查差异后提交并 push。执行 `bash scripts/docker.sh up` 构建和启动，验证健康状态、模型资源和 API 冒烟结果。

本轮不新增医学判断或改动解剖资产，不发送真实健康问题至外部 AI 服务。

## 验证记录

- 全部自动测试通过：69 项（包含 9 项新增目录/加载状态用例）；前后端 TypeScript 与生产构建通过。
- 浏览器检查 1440px 桌面、390px 手机、375×667 短屏和 375×360 压缩视口：组合筛选、疾病→3D→疾病状态保留、详情双向跳转、目录焦点循环/返回、目录末项访问、弹窗快捷键隔离均通过。
- 生产构建通过临时本地代理模拟首次肌肉 GLB 下载返回 503：基础模型保持就绪，重试后恢复；请求记录确认六个基础资产各下载一次，肌肉资源下载两次。
